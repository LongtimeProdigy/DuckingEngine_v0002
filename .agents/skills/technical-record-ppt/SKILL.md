# 기술 기록용 PPT

발표자의 구두 설명 없이 나중에 다시 읽고 코드를 이해할 수 있는 기술 기록을 만든다. 가안 요청이면 구성안을 작성하고, 실제 파일 제작 요청이면 사용 가능한 presentations 스킬의 제작·검증 절차를 함께 따른다.

## 구성

- 전체 실행 흐름과 리소스 흐름을 먼저 제시한다. 각 대분류의 첫 장에는 해당 개념을 한눈에 이해할 수 있는 개념도를 둔다.
- 개념도는 한 슬라이드 안에서 이해할 수 있게 구성한다. PPT 도형을 우선 사용하고 필요하면 이미지를 사용한다.
- 텍스트와 슬라이드 수를 압축하고 그림·수식·핵심 설명을 중심으로 작성한다.
- 기능별 설명 순서는 개념 → 원식 → 근사와 이유 → 출력의 의미·단위 → 사용처를 기준으로 일관되게 맞춘다. 필요한 슬라이드 수는 기능에 맞춘다.
- 본문에는 소스 코드를 넣지 않고, 개념 설명만으로 실제 코드를 다시 읽는 데 도움이 되도록 작성한다.

## 수식과 시각 표현

- 최적화 전 원식을 먼저 보여주고, 근사식은 어떤 이유와 가정으로 유도되는지 비교한다. 가능하면 같은 슬라이드에 배치한다.
- 프로그래밍 변수명보다 통상적인 수학 기호를 사용하고, 각 기호의 의미를 자료 전체에서 통일한다.
- 기호 설명은 식과 같은 줄에 이어 붙이지 않는다. 식의 관련 항에는 짧은 밑줄과 간략한 의미 설명을 붙인다.
- 적분 기호와 결과항을 하나의 밑줄로 묶지 않는다. 수식 내부 간격은 자연스럽게 유지하고 설명 길이에 맞춰 설명 영역을 조절한다.
- 관련 수식 요소를 같은 색으로 묶고 원식과 근사식을 색으로 구분한다. 색은 중요한 부분에만 사용한다.
- 빛의 이동 경로는 개념도로 보여주되, 수식의 결과는 출력 물리량·자료형·단위를 중심으로 설명한다. 실제 사용처에서의 가공은 그 뒤에 설명한다.
- 공통 항과 Rayleigh·Mie 등 개별 항은 시각적으로 구분한다. 정렬은 내용 관계에 맞춰 선택한다.

완성 시 기호 일관성, 원식과 근사식의 정확성, 개념도만으로 이해 가능한지, 잘림·겹침을 확인한다. 이전 버전과 중간 산출물 삭제는 별도로 요청된 범위에서만 수행한다.
