# 엔진 구현·수식 해설

실제 프로젝트 코드를 근거로 설명한다. 사용자가 지정한 함수나 질문에 범위를 맞추고, 설명 요청만으로 코드를 수정하지 않는다.

## 구현 흐름

- 전체 흐름 요청에는 저장 형식·로딩 → CPU 자료구조 → GPU 리소스 배치·업로드·바인딩 → 셰이더 계산 → 출력과 사용처를 연결한다.
- 특정 함수 질문에는 해당 함수의 입력·계산·출력과 이해에 필요한 호출부만 설명한다.
- 주요 변수의 의미, 자료형, 단위, 좌표계와 기준 원점을 명확히 한다. CPU와 HLSL의 대응 멤버를 연결한다.
- 텍스처는 데이터 배치와 샘플링 좌표 계산을 함께 설명한다. 페이지 테이블·아틀라스·LOD가 등장하면 논리적 주소와 실제 상주 데이터를 구분한다.
- 출력 리소스마다 무엇을 저장하고 어느 패스에서 어떻게 사용하는지 보여준다.
- 설명을 실제 파일·함수·라인과 연결하고, 구체적인 수치 예시는 이해에 필요한 경우에만 넣는다.

## 렌더링 수식

- 원식과 각 기호·항의 의미를 먼저 설명한 뒤, 구현에서 사용하는 근사식과 그 근거를 연결한다.
- 기호의 의미를 설명 전체에서 고정한다. 수식과 기호 설명은 시각적으로 분리한다.
- 반환값·출력의 자료형과 물리량·단위를 기준으로 계산 결과를 설명하고, 이후 실제 사용처의 가공 과정을 설명한다.
- 적분, 샘플별 기여, 누적 결과를 구분한다. 산란·투과율·irradiance·radiance처럼 혼동하기 쉬운 양은 해당 질문에 필요한 만큼 구분한다.
- 코드의 근사나 구현 가정을 원래 물리식과 혼동하지 않도록 명시한다.
